# Porting Spec — Casting (Chromecast + DLNA first) from the reference implementation into Aura

Aura has **no casting today** (greenfield). This spec maps the reference implementation's casting subsystem onto Aura's architecture, recommends a phased scope, and gives a file-level, implementable blueprint. The recommended v1 scope is **Chromecast + DLNA**; Roku and AirPlay are deferred (rationale in §5).

---

## 1. What the reference implementation does (architecture + key files)

the reference implementation's casting is a self-contained subsystem: discover devices on the LAN, stand up a **LAN-reachable** HTTP media server that fetches the upstream stream and re-serves it (optionally transmuxed via ffmpeg), then drive the cast device's native protocol (Chromecast CASTV2, DLNA SOAP/AVTransport, Roku ECP, AirPlay HTTP).

### Rust backend
- **`src-tauri/src/cast.rs`** — the orchestrator. Exposes the Tauri commands `cast_discover`, `cast_load`, `cast_play`, `cast_pause`, `cast_seek`, `cast_stop`, `cast_status`. Holds a `static ACTIVE: Mutex<Option<ActiveSession>>` enum (`Chromecast | Dlna | Roku | AirPlay`). `cast_discover` fans out (`tokio::join!`) to all four protocols, dedupes by host (`dedupe_by_host`, kind-priority chromecast>airplay>roku>dlna), sorts by name. `CastDeviceInfo { id, name, host, port, model, kind, control_url, audio_only }` is the wire shape. Auto-remux decision (`needs_auto_remux`): anything that isn't already `.m3u8/.mpd/.ts` gets segmented/transmuxed for chromecast/dlna/roku (non-faststart MP4 + MKV stall otherwise). Chromecast load runs on a **dedicated std::thread** that connects via `rust_cast::CastDevice`, launches the receiver app, sends `media.load_with_opts`, then enters a blocking heartbeat/pong receive loop for the session lifetime. `humanize_cast_error` maps connection failures to user-readable strings.
- **`src-tauri/src/cast_server.rs`** — NOT a generic media server; it's a supervisor for a bundled **`stremio-server` sidecar** (spawn, health-probe `http://127.0.0.1:11470/settings`, auto-restart x3, ffmpeg/ffprobe env injection, orphan-kill on shutdown). **Aura does not use stremio-server and should NOT port this file.** The actual cast media serving in the reference implementation is `stream_proxy.rs` + `cast_hls.rs`.
- **`src-tauri/src/stream_proxy.rs`** — the real cast media server. An axum router bound to **`0.0.0.0:<ephemeral>`** (LAN-reachable, unlike a loopback bridge). `ProxyState` is Tauri-managed state. `register_cast(RegisterArgs)` mints a UUID session, picks a LAN IP that's on the device's subnet (`reachable_ip_for(target_host)` → falls back to `lan_ip()`), and returns an `http://<lan-ip>:<port>/s/<id>` (or `/cast/hls/<id>/master.m3u8` when transcoding, or `/p/<id>/...` for HLS playlist rewriting). Routes: `/s/{id}` (byte-range stream proxy or transcode), `/p/{id}/{*path}` (HLS sub-playlist/segment proxy with codec injection), `/health`. `forward_upstream` server-side-fetches the upstream with reqwest, forwards range headers, **forces a video MIME** when upstream says `application/octet-stream` (cast receivers reject octet-stream), adds permissive CORS, and rewrites m3u8 to inject `CODECS=` so the receiver accepts the playlist.
- **`src-tauri/src/cast_hls.rs`** — on-the-fly HLS emitter for transcoded casts. `register_with_seek` ffprobes the source, mints a temp dir, spawns a **continuous ffmpeg** (`-f hls -hls_time 6 -hls_playlist_type event`, libx264 veryfast + aac, scale-to-1080), serves `master.m3u8` (synthesized), `variant.m3u8` (polls the ffmpeg-written playlist until `#EXTINF` appears), and `.ts` segments (polls until file exists + first byte is `0x47` TS sync). `KillHandle` Drop impl `taskkill /F /T /PID` + removes the temp dir → no orphaned ffmpeg. Idle eviction after 5 min.
- **`src-tauri/src/transcode.rs`** — `locate_ffmpeg()`/`locate_ffprobe()` (huge candidate-path walk: PATH, bundled, chocolatey, scoop, winget, homebrew), `TranscodeProfile { max_height, force_h264, force_aac, force_stereo, max_video_kbps }`, `probe_codecs` (ffprobe → video/audio codec names), and `handle_transcode` (the `/s/{id}` transcode branch: ffprobe to decide copy-vs-reencode, then ffmpeg → MPEG-TS on `pipe:1` streamed to the response body with DLNA content-feature headers). `cast_ffmpeg_present` command.
- **`src-tauri/src/dlna.rs`** — SSDP M-SEARCH discovery (multi-interface, 4 bursts, also passive NOTIFY listener on :1900, Samsung 7676/9197 fallback URLs), device-description XML fetch → `friendlyName`/`modelName`/`manufacturer` + `AVTransport` controlURL, vendor classification (Samsung/LG/Sony/Panasonic/Hisense), then `load`/`play`/`pause`/`stop`/`seek`/`status` via SOAP envelopes (`SetAVTransportURI` + DIDL-Lite metadata + `Play`, vendor-specific MIME + DLNA.ORG_PN profile + pre-stop for Sony). Pure reqwest + hand-rolled XML.
- **`src-tauri/src/roku.rs`** — SSDP `roku:ecp` discovery, ECP launch of the "Media Assistant" channel (`782875`), keypress play/pause/home, `query/media-player` status. **Defer.**
- **`src-tauri/src/airplay.rs`** — mDNS `_airplay._tcp` discovery, legacy `/play` + `/scrub` + `/rate` + `/playback-info` (plist parse). Drops AirPlay-2-only devices. **Defer.**

### Frontend (React)
- **`src/lib/cast.ts`** — typed `invoke()` wrappers: `discoverCastDevices`, `castLoad(opts)`, `castPlay/Pause/Seek/Stop`, `castStatus`, `isFfmpegPresent`, `guessContentType`. Types `CastDeviceInfo`, `TranscodeProfile`, `CastStatus`.
- **`src/lib/cast/device-caps.ts`** — per-device capability matrix (resolution/HEVC/AV1/DV/HDR10/audio-passthrough/MKV) keyed off device name+model regexes, plus `checkStreamCompat`, `pickTranscodeProfile`, `needsTranscode` — decides whether to direct-play or transcode and with what profile.
- **`src/views/player/hooks/use-cast-session.ts`** — the session state machine: menu open/anchor, selected device, pending device, error (+ actionable error modal info), `castPlaying`/`castPositionSec`, a **1 s `castStatus` poll** (polls the cast device, not MPV), `pickCastDevice` (calls `castLoad`, pauses the local bridge), `stopCast` (resumes local MPV at the cast position), `seekCast`. Pauses local playback on cast start; resumes at final position on stop.
- **`src/components/player/cast-menu.tsx`** — the device picker popover (scanning spinner, empty-state with rescan, per-device row with icon + audio badge).
- **`src/components/player/cast-icon.tsx`**, **`transport/cast-button.tsx`** — icon + control-bar button (gated on `capabilities.chromecast || capabilities.airplay`).
- **`src/views/player/cast-session-bar.tsx`** — floating "Casting to <device>" bar with play/pause, ±15s, stop, transcoding badge.
- **`src/views/player/casting-overlay.tsx`** — full-screen "Casting to / Connecting to" splash with blurred poster.
- **`src/views/player/cast-error-modal.tsx`** — actionable error modal (Roku/ffmpeg install steps).

### Data flow (Chromecast direct-play)
`CastMenu` → `cast_discover` (mDNS+SSDP) → user picks device → `use-cast-session.pickCastDevice` → `cast_load` → `register_cast` returns a LAN URL on the proxy → `cast.rs` connects via rust-cast, launches receiver, `media.load(LAN_url)` → device fetches the LAN URL from `stream_proxy` which server-side-fetches the real upstream → `cast_status` polled at 1 Hz → controls via `cast_play/pause/seek/stop`.

## 2. Aura mapping (exact files to create/modify, conventions)

### Aura's relevant architecture
- **`src-tauri/src/streaming.rs`** is only a URL *transformer* (`resolve_stream`). The real proxy is the **separate `aura-bridge` binary** (`aura-bridge/src/main.rs`), bound to **`127.0.0.1:11471` (loopback)**. Loopback is **not LAN-reachable** → a TV cannot fetch from it. **The cast media server therefore needs its own LAN-bound (`0.0.0.0`) listener.** Recommendation (decision #4): run it **in-process** inside the main Aura process as a Tauri-managed state, NOT inside aura-bridge — so cast sessions, HLS temp dirs, and ffmpeg child handles live next to the command handlers (the reference implementation's `stream_proxy` is already in-process; this is the natural port).
- **3-place command registration** (CLAUDE.md): every new `#[tauri::command]` must be (1) added to `lib.rs` `generate_handler!`, (2) a `commands.allow` entry in `permissions/player.toml`, (3) reachable via `capabilities/default.json` (add ONE new permission identifier `allow-cast`).
- **serde rename gotcha**: `CastDeviceInfo`/`CastStatus`/`TranscodeProfile` flow Rust→React. They already use snake_case field names that match TS (`control_url`, `audio_only`, `position_sec`, `player_state`, `max_height`, `force_h264`). Keep `#[derive(Serialize)]` with NO renames (or `rename(deserialize=…)` only) so Tauri emits the Rust names verbatim.
- **ffmpeg is already bundled**: `src-tauri/lib/ffmpeg.exe` exists (used by silencedetect + thumb extractor). **ffprobe.exe is NOT present** → decision #3 (bundle it). Aura's locate logic should prefer `src-tauri/lib/ffmpeg.exe` first, then fall back to the reference implementation's candidate walk.
- **Logging**: use `crate::devlog!(info, "cast", "...")` (new `[cast]` label) instead of the reference implementation's `eprintln!("[cast] ...")`. Add `[cast]` to the label list in CLAUDE.md conventions.
- **Redaction**: route any cast URL logging through `crate::stremio::redact_sensitive_url(...)` (debrid tokens) — the reference implementation logs URLs verbatim; Aura must not.
- **No torrent**: the reference implementation's `needs_auto_remux`/magnet handling is irrelevant — Aura is addon+debrid only. Cast only ever sees http(s) stream URLs.

## 3. Ports 1:1 vs needs-adaptation

### Ports ~1:1 (copy + rename the reference implementation→Aura, swap eprintln→devlog)
- `dlna.rs` SSDP discovery + SOAP load/play/pause/stop/seek/status + DIDL builder + vendor classification — **verbatim** (only UA string + log prefix change).
- `cast_hls.rs` — verbatim (the `KillHandle` Drop/taskkill, polling, master/variant synthesis).
- `transcode.rs` `handle_transcode` + `probe_codecs` + `TranscodeProfile` — verbatim (adjust `locate_ffmpeg` to prefer Aura's bundled path).
- `stream_proxy.rs` `forward_upstream`, `inject_hls_codecs`, `lan_ip`, `reachable_ip_for`, `split_playlist_url`, `guess_ct_from_url` — verbatim.
- `device-caps.ts`, `cast-menu.tsx` logic, `use-cast-session.ts` state machine, `cast-session-bar.tsx`, `casting-overlay.tsx` — logic verbatim; **restyle** to Aura's Tailwind tokens.
- mDNS Chromecast `discover_chromecasts`, `detect_audio_only`, `dedupe_by_host`, `humanize_cast_error`, `normalize_player_state` — verbatim.

### Needs adaptation
1. **Chromecast receiver app id** (decision #2): the reference implementation's `CAST_RECEIVER_APP_ID = "120F754D"` is its private registered CAF receiver — unusable by Aura. **Replace with the Default Media Receiver `"CC1AD845"`** (built into the Cast protocol, no Google registration, plays MP4/HLS/TS). The `launch_receiver_app` machinery is unchanged; only the constant changes. (Optionally register an Aura receiver later for richer UI/subtitles.)
2. **Media server placement**: the reference implementation's `stream_proxy` is in-process and LAN-bound by design. Aura's aura-bridge is a *separate loopback* binary. → Stand up a **new in-process** `0.0.0.0` axum listener (decision #4). Do NOT extend aura-bridge (it's loopback and IPC-separated). Do NOT touch `resolve_stream`'s HTTPS-bypass (that's for local MPV only).
3. **Pause/resume bridge**: the reference implementation's `use-cast-session` talks to a `PlayerBridge`. Aura's equivalent is `usePlayback` + the `toggle_pause`/`seek_absolute` Tauri commands (which already route through the mpv2 engine gate). Provide a thin adapter object.
4. **`cast_server.rs` (stremio-server sidecar)** — **DO NOT PORT.** Aura has no stremio-server. Its HLS/transcode role is covered by `cast_hls.rs` + `transcode.rs` directly.
5. **ffmpeg/ffprobe location**: prefer `current_exe()/../lib/ffmpeg.exe` (Aura's bundled path) and the sibling `ffprobe.exe` before the reference implementation's broad candidate walk.
6. **Logging + redaction**: `eprintln!("[…]")` → `crate::devlog!(_, "cast", …)`, URLs through `redact_sensitive_url`.
7. **Roku/AirPlay arms** — omit from the `ActiveSession` enum and `cast_discover` fan-out for v1 (keep the dedupe/priority code generic so adding them later is additive).

### Phase 4 — ffmpeg transmux (MKV / incompatible streams) — ✅ BUILT (2026-06-12)
- `cast/transcode.rs` (ffprobe codec probe + copy-vs-reencode plan + `should_transmux` heuristic + HLS arg builder) and `cast/hls.rs` (continuous-HLS session registry + ffmpeg `Child` Drop = `taskkill /F /T` + temp-dir removal + 5-min idle eviction + playlist/segment handlers).
- HLS routes (`/hls/:id/:file`) merged into the existing `media_server` listener (NOT a second listener) — the playlist `index.m3u8` and `.ts` segments are served from the per-session temp dir.
- Transmux engages for **Chromecast only** (DLNA renderers decode MKV natively) and only when **ffmpeg AND ffprobe are present** (`cast_ffmpeg_present`); otherwise direct-play. Always transcodes from the head — the resume offset is the device LOAD `currentTime`, so the HLS timeline is 1:1 with real media time (no offset bookkeeping). `-c copy` when the source is already h264/aac (a fast container remux); libx264 veryfast / AAC stereo otherwise.
- `src-tauri/lib/ffprobe.exe` is `.gitignore`d (in `src-tauri/lib/.gitignore`, mirroring ffmpeg.exe) — **the user must drop ffprobe.exe next to ffmpeg.exe** (same ffmpeg archive) for transmux to engage; absent ⇒ direct-play only.
- Frontend: "Transcoding" badge in `CastSessionBar` (driven by `CastStatus.transcoding`, which reflects `hls::is_active()`). A dedicated `CastErrorModal` was NOT needed — the ffmpeg-absent / unsupported-source cases surface a clear backend error through the existing `useCastSession` error state.
- Shutdown: `cast::shutdown_blocking()` (already wired in `window_logic.rs` CloseRequested) now also calls `hls::shutdown()` → every transcode ffmpeg + temp dir is reclaimed on app close.
- **NOT yet hardware-verified** (no Chromecast on hand at build time). `cargo check` + `tsc` clean.

### Phase 5 — DLNA load/control — ✅ BUILT

- **Verify**: cast to a Samsung/LG/Sony TV (DLNA). No new commands (dispatched inside existing ones).

### Phase 6 — Roku + AirPlay — ⛔ DEFERRED INDEFINITELY (low value for Aura)
- **Reason:** low value for Aura at the moment. Aura is a **Windows desktop app** — AirPlay is legacy AirPlay-1 only (which modern Apple devices reject; AirPlay-2 needs pairing not implemented), and Roku requires the user to side-load the free "Media Assistant" channel and flip an ECP network-access toggle (niche, support-burden-heavy). **Chromecast + DLNA already cover the vast majority of TVs.** Revisit only on concrete user demand.
- If ever revived: port `roku.rs` + `airplay.rs` and their `ActiveSession` arms + actionable error modals. The dedupe/priority code in `discovery.rs` is already generic so adding them is additive.

### Shutdown wiring (all phases)
In `lib.rs` CloseRequested / shutdown path: drop/stop `CastProxyState` so HLS ffmpeg children are killed (their `KillHandle::drop` taskkills). Mirror the existing aura-bridge kill-on-close Job Object discipline.

## 5. Recommended SCOPE (decisions echoed in decisionsNeeded)

**v1 = Chromecast + DLNA.** Rationale:
- **Chromecast** — most common cast target; the reference implementation reports it tested-working; with the **Default Media Receiver `CC1AD845`** it needs **zero Google registration**. Highest value.
- **DLNA/UPnP** — broadest TV coverage (Samsung/LG/Sony/Panasonic/Hisense); pure reqwest+SOAP, no extra crate, no receiver app. High value, low marginal cost.
- **Roku — defer.** Requires the user to install the free "Media Assistant" Roku channel and flip an ECP network-access setting; niche, support-burden-heavy.
- **AirPlay — defer.** Aura is **Windows-only** today; legacy AirPlay-1 only (modern Apple devices reject it, AirPlay-2 needs pairing the reference implementation doesn't implement). Lowest value on Windows.

**Receiver:** Default Media Receiver `CC1AD845` (not the reference implementation's private id). **Media server:** new in-process `0.0.0.0` axum listener (not aura-bridge, not loopback). **ffmpeg:** reuse bundled `src-tauri/lib/ffmpeg.exe`; **bundle ffprobe.exe** for the transmux path (or ship direct-play-only v1).

## 6. Effort + risks

**Effort: L** (~1500–2000 LOC, ~14 new files). Discovery+picker = S (~1 day, and a standalone quick win). Chromecast load/control = M. DLNA = S–M. ffmpeg transmux/HLS = M. UI = S. 3-place registration is trivial. Goes XL only if Roku+AirPlay are added.

**Key risks** (full list in `risks`): wrong Chromecast app-id silently breaks every load (must switch to `CC1AD845`); the media server MUST bind `0.0.0.0` (loopback = dead feature) and will trigger a Windows Firewall prompt; ffprobe is absent today (transmux 500s without it); `rust-cast` is lightly maintained + may pull native-tls (pin + verify against Aura's rustls posture); orphaned ffmpeg children need the `KillHandle` taskkill ported verbatim; the cast path deliberately server-side-fetches HTTPS upstreams and re-serves plain HTTP to the device (a sanctioned divergence from `resolve_stream`'s HTTPS-bypass — must not leak into local playback). MPV stability landmines are **not** directly implicated — casting is a parallel path and only pauses/seeks MPV via existing engine-gated commands; add **no** new `observed_properties` and **no** node-format reads; the 1 Hz `castStatus` poll hits the cast device, not libmpv.

## 7. Genuine quick-win sub-part

**Device discovery + picker UI** (Phase 1). It compiles and runs entirely standalone — `cast_discover` (mDNS Chromecast browse + SSDP DLNA) + the `CastMenu` popover — with **no** receiver, ffmpeg, or media-server work, and is independently testable ("do my TVs appear?"). It ports near-1:1 from `cast.rs` discovery fns + `dlna.rs` SSDP + `cast-menu.tsx`. Deliverable in ~1 day: `cast/mod.rs` (discovery + `cast_discover` only), `cast/discovery.rs`, `cast/dlna.rs` (discovery half), `src/cast.ts` (discover only), `src/CastMenu.tsx`, plus the one new `mdns-sd` dep and the 3-place registration for the single `cast_discover` command. Everything past discovery needs the scope/receiver/ffprobe decisions resolved first.

## Decisions needed from the user

1. SCOPE / protocol set: Recommended v1 = Chromecast + DLNA only (covers the vast majority of TVs; both tested-working in the reference implementation). Defer Roku (needs the user to install the free 'Media Assistant' Roku channel + flip an ECP network-access toggle) and AirPlay (legacy AirPlay-1 only; Aura is Windows-only so it's low-value, and modern Apple devices reject AirPlay-1). Confirm Chromecast+DLNA first, or do you want Chromecast-only as an even smaller MVP?
2. Chromecast receiver app: the reference implementation casts to its OWN registered Google Cast CAF receiver (app id 120F754D, repo the reference implementation's cast receiver) which Aura cannot reuse. Recommended: cast to the Default Media Receiver 'CC1AD845' (built into the Cast protocol, ZERO Google registration, plays MP4/HLS/TS once we transmux via ffmpeg). Alternative: register an Aura CAF receiver with Google (needs a Cast SDK dev account + a hosted receiver page, ~1-2 day side-quest, only buys richer UI/subtitles). Confirm CC1AD845.
3. ffmpeg/ffprobe for transmux: Aura already bundles src-tauri/lib/ffmpeg.exe, but ffprobe.exe is NOT in the repo. Transmuxing MKV / non-faststart-MP4 (so Chromecast/DLNA can play them) requires ffprobe. Decision: bundle ffprobe.exe alongside ffmpeg.exe (git-ignored), OR ship v1 as direct-play-only (.mp4/.m3u8/.ts cast; MKV silently unsupported with an 'install ffmpeg' notice). Recommend bundling ffprobe.
4. Cast media server placement: Aura's aura-bridge listens on 127.0.0.1:11471 (loopback) which a TV on the LAN CANNOT reach. The cast server MUST bind 0.0.0.0. Recommended: a NEW in-process axum listener inside the main Aura process (Tauri-managed state), co-locating cast sessions / HLS temp dirs / ffmpeg child handles with the command handlers (the reference implementation's stream_proxy is already in-process). Do NOT extend aura-bridge (loopback + IPC-separated). Confirm in-process 0.0.0.0 listener.
5. Cast button placement: PlayerOverlay top action bar (cast the currently-playing stream; local MPV pauses; the reference implementation's model) vs DetailView stream rows (cast without local playback). Recommend PlayerOverlay first (1:1 with use-cast-session + cast-session-bar). Confirm.
6. LAN exposure: a 0.0.0.0-bound media server serves the (often debrid-tokened) stream to anything on the LAN for the cast session's lifetime, and Windows Firewall will prompt on first cast. Sessions are UUID-pathed and GC'd. Acceptable (same as every cast app)? Recommend yes; flagging because Aura otherwise keeps streams loopback-only and redacts tokens aggressively.

## Risks

- Chromecast app-id: porting verbatim casts to the reference implementation's PRIVATE receiver id 120F754D, which will not work for Aura — every Chromecast load would silently fail. Must switch the one constant to the Default Media Receiver CC1AD845.
- LAN reachability: the whole feature is dead if the media server binds loopback. Must port the reference implementation's lan_ip()/reachable_ip_for() AND bind 0.0.0.0. First cast triggers a Windows Firewall prompt; if the user clicks Cancel/Deny they get a silent failure — needs a clear error + a docs note.
- ffprobe absent today: cast_hls probe + transcode codec-probe both need ffprobe.exe, which is not in the repo. Without it, MKV/incompatible streams 500 unless gated on ffprobe_present() with the 'install ffmpeg' actionable-error UI (which the reference implementation already has to port).
- rust-cast crate is lightly maintained — pin a known-good version; some versions pull native-tls/openssl, which conflicts with Aura's rustls-only posture. Verify the build or accept a transitive native-tls dep (the reference implementation evidently tolerates it).
- MPV landmines NOT directly implicated (cast is a parallel media path; MPV just pauses), but the cast session hook pauses/seeks local playback — it MUST use Aura's existing toggle_pause/seek_absolute commands (already engine-gated), add NO new observed_properties, and do NO node-format get_property reads. The 1 Hz castStatus poll hits the cast DEVICE, not libmpv — safe.
- HTTPS-bypass divergence: Aura normally sends HTTPS straight to MPV (no proxy). For casting, the device usually can't do the same TLS/range, and debrid URLs are HTTPS — so the cast server must server-side-fetch the upstream (reqwest, like the reference implementation's forward_upstream) and re-serve plain HTTP to the device. Correct for cast; must not leak into the local-playback path or undo resolve_stream's bypass.
- Orphaned ffmpeg: cast HLS spawns long-lived ffmpeg children with temp dirs. Port the reference implementation's KillHandle Drop (taskkill /F /T /PID + remove temp dir) verbatim and add a CloseRequested shutdown hook, mirroring Aura's existing aura-bridge kill-on-close Job Object, or risk orphaned ffmpeg.exe holding temp files / WASAPI-adjacent resources.
- Subtitles/tracks: the Default Media Receiver has limited subtitle support and embedded MKV subs won't survive a copy-remux to TS. Acceptable for v1 (no in-receiver sub UI), but set expectations — a custom registered receiver would be needed for rich track/sub control.
