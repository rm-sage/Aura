# Live TV tab (M3U / Xtream / XMLTV EPG) — the reference implementation → Aura porting spec

Greenfield feature for Aura: a new top-level **Live TV** tab that ingests IPTV playlists (M3U/M3U8 URLs and Xtream Codes credentials), parses channels, fetches XMLTV EPG, renders a channel grid + EPG guide, and plays channels through Aura's existing mpv/`load_video` path.

---

## 1. What the reference implementation does (architecture + key files)

the reference implementation's Live TV is **almost entirely frontend TypeScript**. There is no Rust M3U/XMLTV/Xtream parser — `core/src/parser.rs` is the torrent **release-name** parser and is irrelevant here (confirmed: zero `m3u`/`xmltv`/`iptv`/`extinf`/`programme` references). The only Rust touchpoint is the optional **DVR** module.

### Data model (`src/lib/iptv/types.ts`)
- `IptvChannel { id, tvgId, name, logo, group, url, catchupSource, durationSec, attrs }`
- `IptvPlaylist { id, name, url, epgUrl, channels[], fetchedAt, groups[] }`
- `IptvPlaylistSource { id, name, url, epgUrl?, kind?: "m3u"|"xtream"|"epg", xtream?:{server,username,password} }`
- `EpgProgram { channelTvgId, title, description, startMs, endMs, category, iconUrl }`
- `EpgIndex { byChannel: Map<string,EpgProgram[]>, fetchedAt }`

### Parsing
- **M3U** (`src/lib/iptv/m3u.ts`): line-based `#EXTINF:` parser. `parseExtinf` does quoted-attribute tokenization (`tvg-id`, `tvg-name`, `tvg-logo`, `group-title`, `catchup-source`, etc.) with a `lastUnquotedComma` split for the display title; handles `#EXTGRP`, skips `#EXTVLCOPT`/`#KODIPROP`; `isDecorativeRow` drops separator/ASCII-art rows. `groupChannels` buckets by `group-title`. `deriveEpgUrls(playlistUrl)` infers `xmltv.php` / `get.php?type=epg` from an Xtream `get.php`/`player_api.php` URL.
- **Xtream** (`src/lib/iptv/xtream.ts`): `parseXtreamUrl` extracts `{base,username,password}`; `fetchXtreamLiveChannels` calls `player_api.php?action=get_live_categories` + `get_live_streams` in parallel, maps category names, builds the stream URL `${base}/live/${user}/${pass}/${stream_id}.m3u8`. Sends `User-Agent: IPTVSmartersPro/3.1.5`.
- **XMLTV** (`src/lib/iptv/xmltv.ts`): streaming reader — reads the response body in chunks (`getReader()`), incrementally `drainProgrammes` between `<programme …>…</programme>`, hand-rolled attr/childText/CDATA decode (no DOMParser, for 100+MB EPGs). 200 MB cap, 25 s stall-abort. `parseXmltvTime` parses `YYYYMMDDHHMMSS +ZZZZ`. `indexProgramsByChannel` + `findCurrent` (binary search for the on-air program).
- **EPG resolver** (`src/lib/iptv/epg-resolver.ts`): matches a channel's `tvgId` to EPG rows, with a token-overlap guard for shared/ambiguous tvg-ids.

### Network (CRITICAL adaptation point)
All fetches detect Tauri and use **`@tauri-apps/plugin-http`** (`import("@tauri-apps/plugin-http")`) with custom `User-Agent`, `connectTimeout`, `maxRedirections` — this is how the reference implementation **bypasses CORS** and sends IPTV-client UAs that providers gate on. Browser `fetch` is only the web fallback. **Aura has neither `tauri-plugin-http` (JS) nor the Rust `tauri-plugin-http` crate** — this is the single biggest forced change (see §3).

### State stores (module-level singletons, not React context)
- `store.ts`: `loadPlaylist(src,{force})` with 6 h TTL cache + in-flight dedup + pub/sub `subscribePlaylists`. Tries Xtream first, falls back to M3U. Rich HTTP error classification (401/403/404/429/503, DNS, reset, "inactive", too-large 80 MB cap).
- `epg-store.ts`: `loadEpg({playlistId,urls,force})`, 1 h TTL, multi-URL fallback, progressive `onProgress` updates as the stream parses.

### React UI (`src/views/live.tsx` + `src/views/live/**`)
- `LiveView`: reads `settings.iptvPlaylists`, tracks `activeId` (localStorage `aura.iptv.active`), view `mode` ∈ grid|guide|multiview (`aura.iptv.viewMode`). Hooks: `useIptvPlaylist`, `useEpg`+`useNowTick(30s)`, `useChannelFilter`, `useFavorites`. Left **CategorySidebar** (groups + favorites + counts), header with **SourcePicker** (add/edit/remove/refresh/export playlists) + search box + **ViewModeToggle**.
- **Grid mode** (`channel-grid.tsx` + `channel-card.tsx`): `auto-fill minmax(200px,1fr)` cards; each shows logo/poster, a LIVE pill, current EPG program + progress bar + "Xm left" + "Next:", favorite + info buttons. `useLazyVisible` (IntersectionObserver windowing), optional Cinemeta "hydration" for VOD-ish channels (out of scope for the port).
- **Guide mode** (`live/guide/*`): horizontal timeline (`PX_PER_MIN=5`, 8 h window, resizable channel column persisted to localStorage), sticky time ruler, per-program blocks, a red "Now" line, catchup-replayable ended programs.
- **Playback**: `handlePlay(ch)` synthesizes a fake `Meta` (`type:"tv"`) and calls the reference implementation's `openPlayer({ meta, url: ch.url, title, subtitle, notWebReady:true, liveProgram })`. `notWebReady` tells the player it's a live stream (no seek bar, reconnect-on-stall). Catchup builds a timeshift URL (`catchup.ts`) and plays that.
- `PlaylistForm` (`source-picker/playlist-form.tsx`): 3-type form (M3U URL / Xtream server+user+pass / EPG-only). `buildXtreamUrls` produces `get.php?...type=m3u_plus&output=ts` + `xmltv.php`.
- `export.ts`: `buildM3u` serializes channels back to `.m3u` (uses `@tauri-apps/plugin-dialog` save + `plugin-fs` write — also absent in Aura).

### DVR (`src-tauri/src/dvr.rs`) — the only Rust
Spawns an **external `mpv.exe`** (`locate_mpv` looks for `mpv` on PATH) with `--stream-record=out.ts --vo=null --ao=null` for a planned duration, emits `dvr://progress|done|error`. Commands: `dvr_start/stop/list/default_dir/reveal`. **Aura ships libmpv DLLs, not a standalone `mpv.exe`**, so DVR does not port cleanly (see §3, deferred).

### Conventions Aura requires (from CLAUDE.md / HANDOFF)
- **3-place command registration** for every new Rust command: (1) `src-tauri/src/lib.rs` `tauri::generate_handler![…]`, (2) `src-tauri/permissions/player.toml` `commands.allow=[…]` (define an `allow-iptv` permission set), (3) `src-tauri/capabilities/default.json` permissions array. Miss one → silent 401.
- **serde rename(deserialize)**: any struct that flows Rust→React (`IptvPlaylistSource` in `AppSettings`) must use `#[serde(rename(deserialize="…"))]` if wire names differ from Rust snake_case, so Tauri's *outgoing* JSON keeps Rust field names matching the TS interface. Cleanest: name Rust fields to match the TS camelCase you want, or keep the TS interface snake_case.
- **Tailwind opacity scale gotcha**: only use opacity steps from the extended scale (`tailwind.config.ts`); arbitrary `/97` etc. silently emit no CSS.
- **MPV stability landmines do NOT apply** to Live TV playback — it reuses the exact `resolve_stream`→`load_video` path. Do not add new observed properties, do not poll during load. One real concern: HLS live has no fixed `duration`; Aura gates a lot of polling on `duration>0`. Verify the loading overlay and track-read path tolerate `duration==0`/`duration==inf` for live (likely fine — just never fires the one-shot track read; acceptable). This is the **#1 thing to smoke-test**.
- **devlog label**: add `[iptv]` to the Rust log-label list (CLAUDE.md Conventions) and use `crate::devlog!(info,"iptv",…)`.
- Frontend reads Rust settings via `invoke("get_settings")` / `invoke("update_settings", {patch})` (see `SettingsView.tsx`). Mirror that for `iptv_playlists`.

## 3. Ports 1:1 vs needs-adaptation

### Ports ~1:1 (pure logic, copy + retype imports)
- `m3u.ts` (parseM3u, parseExtinf, groupChannels, deriveEpgUrls, isDecorativeRow) — **verbatim**.
- `xmltv.ts` parsing half (`parseXmltv`, `drainProgrammes`, `parseProgramme`, `parseXmltvTime`, `indexProgramsByChannel`, `findCurrent`) — **verbatim**. Only the `iptvFetch` network shim is replaced.
- `xtream.ts` (`parseXtreamUrl`, `buildLiveStreamUrl`, URL/param building) — verbatim except `xtreamFetch` → invoke a Rust JSON fetch.
- `epg-resolver.ts`, `types.ts`, `catchup.ts` (timeshift URL building) — verbatim.
- `useChannelFilter`, `useEpg`/`useNowTick`, `useIptvPlaylist`, `guide-utils.ts` and guide geometry — verbatim (restyle only).
- Channel grid/card/guide components — structure verbatim, **restyle to Aura tokens**.
- `export.ts::buildM3u` (serializer) — verbatim; only the dialog/fs write is adapted.

### Needs adaptation (Aura architecture forces it)
1. **Network fetching → Rust.** the reference implementation's `@tauri-apps/plugin-http` is absent. Add `src-tauri/src/iptv.rs` with:
   - `iptv_fetch_text(url, ua_kind) -> Result<String,String>` — reqwest GET with the right UA (`VLC/3.0.20 LibVLC/3.0.20` for M3U/XMLTV, `IPTVSmartersPro/3.1.5` for Xtream), 30 s connect timeout, redirect-follow, 80 MB cap for M3U / 200 MB for XMLTV, returns the body string. This **also solves CORS** (provider hosts rarely send CORS headers; webview `fetch` would fail) and lets providers' UA-gating pass.
   - `iptv_fetch_json(url) -> Result<serde_json::Value,String>` (or reuse `_text` + `JSON.parse` on the frontend) for Xtream `player_api.php`.
   - Rich error classification can stay frontend-side (the reference implementation's `classifyError` is string-based) OR move into Rust; recommend keep frontend `classifyError` and just surface the reqwest error string.
   - **Streaming XMLTV note:** the reference implementation streams + incrementally parses 100MB+ EPGs. A single `iptv_fetch_text` Rust call returns the whole body at once — fine for ≤30–50 MB EPGs, but loses progressive UI and risks a big string. For v1 accept whole-body (cap 64 MB, warn above); a Phase-3+ enhancement is a Rust streaming parser emitting `iptv://epg-progress` events.
2. **`iptv_playlists` persistence.** Lives in Rust `AppSettings` (Decision §5-A). Add `IptvPlaylistSource` Rust struct + `Vec<IptvPlaylistSource>` field, default `[]`. Xtream `username`/`password` are secret-ish — Aura already has `api_keyring.rs` (`get_api_key`/`set_api_key`); consider storing Xtream creds in keyring keyed by playlist id rather than plaintext settings.json (Decision §5-D).
3. **Playback wiring.** No `notWebReady` concept in Aura. Two options: (a) thread a `isLive` flag through `handlePlayStream`→playback state so PlayerOverlay hides the scrubber and skips resume/scrobble/history for `iptv:` targets; (b) minimal v1 — just call `handlePlayStream` with a synthetic stream/target and let the normal overlay show (scrubber will be inert for an infinite live stream). Recommend (a) — small, and prevents Live TV polluting Continue-Watching/History. Gate: `target.media_type === "tv"` or `id.startsWith("iptv:")`.
4. **Export `.m3u`.** Needs file-save. Either add `tauri-plugin-dialog`+`-fs`, or a `iptv_export_m3u(suggested_name, body)` Rust command using `rfd`/native save + `std::fs`. Low priority → Phase 4.
5. **DVR** — deferred (no `mpv.exe`). If wanted later, port `dvr.rs` but make it spawn ffmpeg (Aura already references a git-ignored `ffmpeg.exe` for silencedetect per memory) or a headless libmpv instance.
6. **Multiview** — the reference implementation renders 4 simultaneous channels; Aura's single embedded MPV child can't do this without a render-API rewrite. **Out of scope.**
7. **Cinemeta channel hydration** (poster enrichment) — optional, depends on the reference implementation's `cinemeta.ts`/`safe-fetch`. Aura has `metaCache.ts`; could wire later. **Skip in v1.**

## 5. Decisions the user must make
- **A. Where does `iptv_playlists` live** — Rust `AppSettings` (round-trips through `get_settings`/`update_settings`, syncs with the rest, recommended) **vs** frontend-only `localStorage`/`auraSettings.ts` (simpler, but not in Aura's settings backup/sync). Recommend Rust `AppSettings`.
- **B. Scope cut** — confirm v1 = **M3U + Xtream + EPG guide**, and that **DVR, Multiview, Cinemeta-hydration, top-networks/region rows are all out of scope**. (Recommended.)
- **C. Network fetch approach** — confirm a **Rust reqwest fetcher** (`iptv_fetch_text/json`, solves CORS + UA gating, no new plugin) vs adding `tauri-plugin-http` (closer to the reference implementation's code but a new dependency + capability surface). Recommend Rust fetcher.
- **D. Xtream credential storage** — plaintext in settings.json (simple) vs `api_keyring.rs` keyring (consistent with Aura's secret-handling stance in HANDOFF §11). Recommend keyring for username/password.
- **E. `isLive` playback path** — add an `isLive` flag through `handlePlayStream`/playback state to suppress scrubber/resume/scrobble/history for live (recommended), vs minimal "just play it through the normal overlay" for v1.
- **F. EPG fetch strategy** — accept whole-body fetch w/ 64 MB cap for v1 (simple) vs build a Rust streaming XMLTV parser with progress events (matches the reference implementation's UX on huge EPGs, more work). Recommend whole-body for v1.

## 6. Effort + risks

**Effort: L** (Phase 1 M3U MVP is M; +Xtream is S; +EPG/Guide is M–L; the long pole is restyling the reference implementation's `live/**` components to Aura's design language and the guide grid). Pure parsers port verbatim and are cheap.

**Risks:**
- Live HLS has **no fixed `duration`** — Aura gates polling/track-reads/UI on `duration>0`. Must verify the loading overlay, PlayerOverlay, and the broken-stream watchdog (45 s no-first-frame) behave for an infinite live stream. Highest-risk integration point.
- Aura's broken-stream **load watchdog** (45 s) + stale-heartbeat detector may false-positive on slow-starting IPTV channels; may need an `isLive` carve-out.
- **CORS / UA gating**: confirmed Aura has no http plugin, so webview `fetch` to provider hosts will fail CORS — the Rust fetcher is mandatory, not optional.
- **Big EPG strings**: whole-body fetch of a 50–100 MB XMLTV through a single `invoke` return is memory-heavy and may stall the IPC bridge; the 64 MB cap + "EPG too large" message mitigates, streaming parser removes it.
- **serde rename(deserialize)** trap on `IptvPlaylistSource` flowing Rust→React (CLAUDE.md): get this wrong and the frontend reads `undefined` for `epgUrl`/`xtream`.
- Live `.ts` (HTTP) streams route through the **127.0.0.1:11471 bridge proxy**; verify the bridge handles long-lived chunked/`Transfer-Encoding` live streams (it was built for byte-range VOD). HTTPS `.m3u8` bypasses the bridge and is lower-risk.
- Provider instability (expired creds, max-connections 503) is normal — the reference implementation's `classifyError` is worth porting verbatim for good UX.

## Risks

- Live HLS has no fixed duration; Aura gates polling/track-reads/UI/watchdogs on duration>0 — must verify loading overlay, PlayerOverlay scrubber, broken-stream watchdog, and stale-heartbeat detector tolerate an infinite live stream (highest-risk integration point).
